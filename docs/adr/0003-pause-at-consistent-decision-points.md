# Pause at consistent decision points

A Decision Batch pauses the entire simulation at a consistent state while no simulation time advances. All requests at that pause point observe the same state; their responses are jointly validated and then applied atomically, with conflicts invoking an explicit fallback or abort rule. Triggers react to state transitions and define re-arm conditions or hysteresis plus a deduplication key, preventing unchanged state from producing an infinite decision loop. The host may wait indefinitely in wall-clock time, and invalid or unavailable responses invoke an explicitly configured Fallback Policy rather than an implicit default; this favors reproducible training data and comprehensible decision traces over concurrent progress in unrelated production areas.
